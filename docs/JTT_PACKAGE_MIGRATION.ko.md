# JTT 배포 패키지 전환 계획

공개 JTT RC3는 배포명 `tmux-agent-tower`, 버전 `0.3.0rc3`를 유지합니다.
이 후보는 RC3 태그, Release 자산, 설치기 또는 기존 설치를 변경하지 않습니다.

후속 배포 후보는 `ju0-terminal-tower` 버전 `0.3.1rc0`입니다. 아직 공개되지
않았고 PyPI에서 설치할 수 없습니다. 후보 Wheel은 Python 코드를
`ju0_terminal_tower` 경로에 설치하고 `jtt` 명령만 제공합니다. 내부 공용 import를
위한 호환 별칭은 기존 배포명이나 다른 `tmux_agent_tower` 소스가 없을 때만
허용됩니다. 후보와 RC3는 별도 Python 환경에 둡니다.

## 설치 관리 주체

pipx와 uv 설치의 설치·업그레이드·삭제 주체는 해당 패키지 관리자입니다. JTT 자체
업데이트와 롤백은 패키지 관리자가 소유한 설치를 변경하지 않도록 거부합니다.
PyPI에서 후보 이름을 사용할 수 있는지 또는 소유권이 누구에게 있는지 확인되지
않았습니다. 별도 게시 승인이 있기 전에는 인덱스에서 설치하지 마세요.

격리 시험용 환경 예시:

```sh
PIPX_HOME=/tmp/jtt-test/pipx PIPX_BIN_DIR=/tmp/jtt-test/pipx-bin pipx install ./dist/ju0_terminal_tower-0.3.1rc0-py3-none-any.whl
UV_TOOL_DIR=/tmp/jtt-test/uv-tools UV_TOOL_BIN_DIR=/tmp/jtt-test/uv-bin uv tool install ./dist/ju0_terminal_tower-0.3.1rc0-py3-none-any.whl
```

위 경로는 폐기 가능한 시험 환경 예시이며, 현재 사용자 설치 명령이 아닙니다.
설치 후 `jtt`의 절대 경로와 `jtt --version`을 확인하세요. 이미 `jtt`가 있으면
덮어쓰지 말고 중단해 충돌을 명시적으로 해결해야 합니다.

격리 충돌 시험에서 pipx 1.18.4는 종료 코드 0과 경고를 반환했지만 기존 `jtt` 파일을
보존하고 새 앱을 해당 경로에 노출하지 않았습니다. uv 0.13.5는 종료 코드 2로 실패했고
기존 `jtt`·`tower` 파일을 보존했습니다. 덮어쓰기/강제 옵션을 사용하지 마세요. 기존
`jtt`를 유지해야 하면 별도 패키지 관리자 실행 파일 디렉터리를 사용하세요.

## RC3에서 수동 전환

RC3 자동 이전은 없습니다. 기존 런처와 Python 환경을 그대로 보존합니다. 향후 별도
승인된 전환은 다음을 수행해야 합니다.

1. RC3 런처 경로를 기록하고 `jtt --version`이 공식 `0.3.0rc3`을 표시하는지 확인합니다.
2. 새 배포를 pipx 또는 uv의 별도 환경과 별도 실행 파일 디렉터리에 설치합니다.
3. PATH나 셸 설정을 바꾸기 전에 새 절대 실행 경로, 후보 버전, 읽기 전용
   `jtt doctor` 출력을 확인합니다.
4. 기존 JTT_HOME은 데이터 형식을 확인하고 세션 ID·generation·PID를 기록한 뒤에만
   재사용을 고려합니다. 설치 과정에서 세션 상태를 쓰거나 프로세스를 재시작하면 안 됩니다.
5. 검증이 실패하면 RC3 런처를 계속 사용하고 패키지 관리자 명령으로 후보만 제거하며
   JTT_HOME은 그대로 둡니다.

RC3 Supervisor의 신원 검증은 RC3의 `_worker.py` 경로에 결합되어 있습니다. 후보 배포는
이를 다시 연결하지 않습니다. 버전이 다른 worker 경로를 신뢰 기록 없이 허용하면 오래된
세션 보호가 약해지므로 이 검증을 완화하지 않았습니다. RC3 세션이 실행 중이면 후보를
기존 JTT_HOME에 연결하지 마세요. 기존 런처와 JTT_HOME을 함께 보존하고, RC3 세션이
기존 런타임에서 종료될 때까지 별도의 후보 JTT_HOME을 사용하세요. 파일을 보존하는 것과
버전 간 실시간 세션 재연결은 다릅니다.

설치·업그레이드·롤백·삭제 과정에서 Supervisor나 PTY를 종료하지 않습니다. RC3 활성
세션이 모두 없어진 뒤에도 저장 작업공간을 재사용하려면 기존 JTT_HOME 백업과 데이터
호환성 확인을 포함하는 별도 명시적 이전 절차가 필요합니다. 자동 복사나 이전은 이 후보에
포함되지 않습니다.

이 문서는 안전 경계만 설명하며 사용자 설치 이전, PATH 변경 또는 실행 중 세션 이전을
승인하지 않습니다.
